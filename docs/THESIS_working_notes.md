# Обзор продукта Scenica

## Назначение

**Scenica** — информационная система для управления театром или сетью театров.
Она закрывает операционный контур театрального предприятия и одновременно даёт
зрителям самостоятельный канал покупки билетов.

## Предметная область

Система охватывает:

- **Организационную структуру**: франшизы, театры, залы, сотрудники с ролями.
- **Репертуар**: сценарии, акты и части сценария.
- **Показы и билеты**: расписание показов, места, бронирования и продажи.
- **Клиентов**: учётные записи зрителей, их бронирования и голосования
  (обычные и VIP).
- **Ресурсы**: оборудование и услуги, а также их аренда под конкретный показ.

## Интеграция с генерацией сценариев

Файл технического задания сценария можно загрузить через API, скачать обратно и
отправить во внешний workflow **n8n**, где с ТЗ работает нейросетевой узел.
Ответ workflow сохраняется в карточке сценария как результат обработки.

Настройка интеграции:

| Переменная | Назначение |
|------------|------------|
| `N8N_TZ_WEBHOOK_URL` | POST-вебхук n8n. Пусто — обработка отключена. |
| `N8N_TZ_TIMEOUT_SEC` | Таймаут запроса к n8n в секундах (по умолчанию 120). |
| `SCENARIO_TZ_UPLOAD_ROOT` | Каталог хранения загруженных файлов на стороне API. |

См. эндпоинты `POST /scenarios/{id}/tz-spec/upload`,
`GET /scenarios/{id}/tz-spec/download` и
`POST /scenarios/{id}/tz-spec/process` в [API_DOCS.md](API_DOCS.md).

## Пользователи и каналы доступа

| Пользователь | Канал | Возможности |
|--------------|-------|-------------|
| Сотрудники | Десктопный клиент (PySide6) | Выборки, поиск и сортировка, CRUD, дашборд, работа с ТЗ сценариев |
| Зрители | Android-приложение (Compose) | Регистрация и вход, театры и показы, схема мест, бронирования |
| Внешние интеграции | HTTP API | Публичные эндпоинты `/public/v1/*` и вебхук n8n |

## Технические решения

- **Единый API вместо прямого доступа к БД.** Оба клиента работают только через
  HTTP API, что упрощает контроль доступа и развитие системы; подробнее —
  в [COMPARISON.md](COMPARISON.md).
- **Ролевая модель.** Права на чтение и изменение проверяются на сервере
  (`api/rbac.py`), а интерфейс дополнительно скрывает недоступные действия.
- **Безопасность паролей.** Пароли хранятся только в виде bcrypt-хешей, вход
  выдаёт JWT с ограниченным сроком жизни.
- **Общая кодовая база.** Десктопный и мобильный клиенты используют один и тот
  же backend, поэтому логика учёта не дублируется.
